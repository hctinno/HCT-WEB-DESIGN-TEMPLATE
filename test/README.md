# 테스트

```bash
npm test
```

의존성이 없습니다. Node 내장 `node:test` 를 그대로 씁니다 — 이 저장소의 검사
스크립트가 전부 순수 node 인 것과 같은 이유입니다. 테스트 러너를 고르는 일에
시간을 쓰고 싶지 않고, 설정 파일이 하나 더 늘어나는 것도 원하지 않습니다.

## 실행 명령의 따옴표에 주의하세요

```json
"test": "node --test test/*.test.mjs"     ← 따옴표 없음
```

**글로브를 따옴표로 감싸면 Node 20 에서 깨집니다.** `--test` 의 글로브 확장은
Node 22 부터입니다. 감싸지 않으면 셸이 먼저 파일 경로로 펼쳐서 넘기므로 어느
버전에서든 동작합니다.

로컬(Node 22)에서는 감싸도 통과해서 못 보고 넘어갔고, CI(Node 20)가 잡았습니다:

```
Could not find '.../test/*.test.mjs'
```

CI 의 Node 를 올려서 이 신호를 없애지 마세요. 소비 프로젝트가 어떤 Node 를
쓸지 모르고, 이 차이를 알려주는 건 지금 CI 뿐입니다.

## 무엇을 테스트하는가

**순수 로직만** 테스트합니다: 질의·필드·CSV·가져오기 검증·지표·차트 토큰.

화면은 테스트하지 않습니다. 화면은 `npm run audit:a11y`(전 화면 × 2폭 ×
2테마)와 브라우저에서 직접 봐서 확인합니다. React 렌더링 테스트를 붙이면
jsdom·testing-library 같은 의존성이 줄줄이 딸려오는데, 그것이 잡아주는 것보다
지금은 **로직 층의 조용한 오답**이 훨씬 위험합니다.

로직 층은 스키마 하나에서 표·보드·상세·필터·대시보드가 전부 파생되기
때문입니다. `applyQuery` 가 조용히 틀리면 **모든 화면이 함께 틀립니다.**

## 이 파일들이 존재하는 이유

이 저장소에서 지금까지 발견된 버그는 **전부 이 층에 있었고, 전부 우연히
발견됐습니다.**

| 버그 | 어떻게 발견했나 |
|---|---|
| `formatRelative` 가 미래 날짜를 전부 "방금" 으로 | 모니터링 앱을 만들어보다 |
| `applyQuery` 가 오타 난 연산자에서 필터를 조용히 해제 | 예시에서 `op:` 라고 잘못 씀 |
| `foldSeries` 의 `valueOf` 옵션이 기본값을 못 받음 | 버리는 스크립트를 하나 써보다 |

세 번째는 **화면이 죽는 버그**였는데, 대시보드 기본 차원이 값 4개짜리라
화면을 봐서는 드러나지 않았습니다. 담당자별로 바꾸는 순간 죽었습니다.

우연에 기대는 것을 그만두려고 만들었습니다. 그래서 **각 버그는 회귀
테스트로 남아 있습니다** — 주석에 `회귀:` 로 표시된 것들입니다.

## 새 테스트를 쓸 때

- 버그를 고쳤으면 **그 버그를 재현하는 테스트를 먼저** 남기세요. 고치기만
  하면 다음 사람이 같은 자리에서 같은 실수를 합니다.
- 함수가 무엇을 하는지가 아니라 **무엇을 약속하는지**를 테스트하세요.
  "분해 조각의 합은 총계와 같다" 는 구현이 바뀌어도 지켜져야 하는 약속입니다.
- 실패 메시지에 기대값과 실제값이 함께 나오도록 `assert.deepEqual` 계열을
  쓰세요. `assert.ok(a === b)` 는 무엇이 틀렸는지 안 알려줍니다.
