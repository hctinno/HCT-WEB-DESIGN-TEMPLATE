# 상태 색상 체계

## 문제

여러 에이전트가 각자 화면을 만들면 이런 일이 벌어집니다.

- 에이전트 A: "진행중"을 파란색으로
- 에이전트 B: "진행중"을 주황색으로
- 에이전트 C: "진행중"을 회색으로

사용자는 색을 보고 상태를 판단하는 법을 배우지 못합니다.
관리도구에서 이건 단순한 미관 문제가 아니라 **판단 속도의 문제**입니다.

## 해결 — 색 선택권을 주지 않는다

색은 **필드 스키마**에서 한 번 정해집니다. 화면은 관여하지 않습니다.

```js
{ key: 'status', label: '상태', type: 'select', options: [
    { value: 'doing', label: '진행중', status: 'inProgress' },
    //                                 ^^^^^^ 이 키가 색을 결정합니다
]}
```

이 한 줄 덕분에 "진행중"은 표에서든 보드 컬럼에서든 상세 패널에서든
대시보드 분해 막대에서든 같은 파란색입니다. 어느 화면이든 스키마를 거치기
때문입니다.


`StatusBadge` 는 색상 prop 을 받지 않습니다. 워크플로 상태 이름만 받습니다.

```jsx
<StatusBadge status="inProgress" dot />
```

색과 라벨은 시스템이 정합니다. 어느 화면에서든 동일합니다.

## 상태 표

| status | 색조 | 기본 라벨 | 의미 |
|---|---|---|---|
| `todo` | 회색 | 대기 | 아직 시작하지 않음 |
| `inProgress` | 파랑 | 진행중 | 처리 중 |
| `inReview` | 보라 | 검토중 | 확인 대기 |
| `blocked` | 빨강 | 차단됨 | 외부 요인으로 멈춤 |
| `done` | 초록 | 완료 | 정상 종료 |
| `failed` | 빨강 | 실패 | 오류로 종료 |
| `pending` | 주황 | 보류 | 조건 대기 |
| `active` | 초록 | 활성 | 사용 중 |
| `inactive` | 회색 | 비활성 | 사용 안 함 |

라벨은 `children` 으로 덮어쓸 수 있지만, **색조는 바꿀 수 없습니다.** 의도된 제약입니다.

## 색조의 의미 (일관성 유지)

| 색조 | 언제만 쓰는가 |
|---|---|
| 초록 (success) | 정상 완료. "좋은 상태" |
| 파랑 (info) | 진행·정보. 좋고 나쁨의 판단 없음 |
| 주황 (warning) | 주의 필요. 아직 실패는 아님 |
| 빨강 (danger) | 실패·차단·파괴적 동작 |
| 보라 (review) | 사람의 확인 대기 |
| 회색 (neutral) | 상태 없음·비활성 |

**빨강을 남용하지 마세요.** 모든 것이 빨갛다면 아무것도 급하지 않습니다.

## 색상만으로 의미를 전달하지 않습니다

`StatusBadge` 는 색과 **텍스트 라벨을 항상 함께** 표시합니다.
남성의 약 8%가 색각 이상을 갖고 있고, 색만으로 구분되는 인터페이스는 그들에게 무의미합니다.

밀집 테이블에서 공간이 부족하면 `dot` prop 으로 점을 추가하되,
라벨은 여전히 유지하세요. 점만 남기지 마세요.

## 증감 표시의 함정

증가가 항상 좋은 것은 아닙니다.

```jsx
<StatCard label="처리 건수" value="128,430" delta={12.4} />              {/* 증가 = 초록 */}
<StatCard label="오류율" value="0.42" unit="%" delta={1.8} invertDelta /> {/* 증가 = 빨강 */}
```

`invertDelta` 를 빠뜨리면 오류율 상승이 초록색으로 표시됩니다.
**낮을수록 좋은 지표**(오류율, 응답시간, 이탈률, 비용)에는 반드시 넘기세요.
